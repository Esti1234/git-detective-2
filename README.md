# Git Detective 🔍-?

ברוכות הבאות לתרגיל המסכם בנושא Git ו־GitHub!

בריפו הזה יש אתר קטן של **רשימת משימות** (My Tasks).
אין צורך לדעת HTML או JavaScript – המטרה היא לתרגל **Git**:
branches, commits, Pull Request, Code Review, Rebase ופתרון Conflict.

האתר עובד בלי שרת ובלי התקנות: פשוט פותחים את הקובץ `index.html` בדפדפן.

## עובדות בזוגות

הריפו הזה משותף לשתיכן. באתר יש **שני באגים**, ויש **שני ענפי פיצ'ר** שצריך לעדכן.
כל אחת מכן מטפלת בחלק משלה, והחברה לזוג בודקת לה ומאשרת (Approve):

| | בת א' | בת ב' |
|---|---|---|
| הבאג שלי | הרשימה לא מוצגת | הכפתור **Add Task** לא קריא |
| branch לתיקון הבאג | `bugfix/task-list-rendering` | `bugfix/add-button-style` |
| ענף הפיצ'ר שלי | `feature/task-filters` (סינון משימות) | `feature/task-counter` (מונה משימות) |

## כללים

- לא עובדים ישירות על `main`. כל שינוי נעשה ב־branch נפרד ומגיע ל־`main` רק דרך Pull Request.
- **אף Pull Request לא ממוזג בלי Approve מהחברה לזוג.** את ה־PR שלך ממזגת את, אחרי שקיבלת Approve.
- הודעות commit צריכות להיות קצרות וברורות.
- נתקעת? שאלי. כמעט תמיד אפשר לחזור אחורה.

---

## משימה א — תיקון באג ו־Pull Request

1. שכפלי (clone) את הריפו המשותף למחשב שלך.
2. פתחי את `index.html` בדפדפן. שימי לב: יש בו שני באגים, **את מטפלת רק באחד**, לפי הטבלה למעלה. גלי למה הוא קורה. (רמז: כלי המפתחים של הדפדפן, מקש `F12`.)
3. צרי branch חדש עם השם שמופיע בטבלה.
4. תקני את הבאג ובדקי שהאתר עובד.
5. בצעי commit עם הודעה ברורה, ודחפי את ה־branch ל־GitHub.
6. פתחי Pull Request אל `main`, עם כותרת ותיאור: מה היה הבאג ומה תיקנת. בקשי מהחברה שלך להיות Reviewer.
7. **בדיקה (Review) של החברה:** פתחי את ה־Pull Request של החברה שלך, עברי על **Files changed**, וודאי שהשינוי קטן ומתאים לבאג שתואר. אפשר להוסיף הערה על שורה. אם הכול תקין, בחרי **Approve**. אם לא, בחרי **Request changes** וכתבי מה לשנות.
8. אחרי שקיבלת Approve, מזגי את ה־Pull Request שלך.

לפני שעוברות למשימה ב', וודאו ששני תיקוני הבאגים מוזגו ל־`main`.

---

## משימה ב — Rebase ופתרון Conflict

בזמן שתיקנתן את הבאגים, עבדו על פיצ'רים חדשים, כל אחד בענף משלו (ראי בטבלה איזה ענף הוא שלך).
הענף נבנה לפני ש־`main` השתנה, והמטרה היא לעדכן אותו כך שייבנה על `main` העדכני.

1. עברי לענף הפיצ'ר שלך.
2. עדכני את המידע על הענפים המרוחקים (`git fetch`).
3. בצעי Rebase של הענף על `origin/main`.
4. Git יעצור בגלל **Conflict**. זהי באיזה קובץ ובאיזה חלק בו, ופתרי אותו ידנית.
5. שמרי **גם את השינוי של `main` וגם את הפיצ'ר שלך**.
6. המשיכי את ה־Rebase, בדקי שההיסטוריה תקינה, ופתחי את האתר: הכול צריך לעבוד.
7. דחפי את העדכון ל־GitHub ופתחי Pull Request אל `main`.
8. **בדיקה של החברה:** מי שבודקת צריכה להוריד את הענף אל המחשב שלה ולפתוח את האתר, כי לא מספיק לקרוא את הקוד. בדקי ב־**Files changed** שאין שאריות של סימני Conflict (`<<<<<<<`, `=======`, `>>>>>>>`), ששני השינויים נשמרו, ושהאתר עובד. אם הכול תקין, **Approve**.
9. אחרי Approve, מזגי את ה־Pull Request.

### טיפים

- הסתבכת באמצע ה־Rebase? אפשר לבטל אותו ולהתחיל מחדש.
- אחרי Rebase ההיסטוריה של הענף משתנה, ולכן ייתכן ש־push רגיל יידחה. קראי את ההודעה של Git וחשבי מה הדרך הבטוחה להתמודד איתה.
- אם החברה שלך כבר מיזגה את הפיצ'ר שלה, ייתכן שתצטרכי לעדכן את הענף שלך שוב. זה חלק מהעבודה בצוות.

בהצלחה, בלשיות! 🕵️‍♀️
